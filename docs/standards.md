# 규칙 (어기면 깨지는 것)

## 파일과 의존성

- 앱은 `index.html` 한 파일이다. 파일을 쪼개거나 빌드 단계를 넣지 않는다.
- `<script>` 블록은 **하나**다(문법 검사가 `blocks: 1`을 확인한다). 카카오 SDK는 `<script src>` 태그로 넣지 않고 `loadKakao()`가 필요할 때 요소를 만들어 넣는다.
- 외부 의존성은 카카오 지도 SDK 하나다. 새 라이브러리·폰트·CDN을 넣지 않는다.
- 배포에 필요한 파일은 `index.html`, `manifest.webmanifest`, 아이콘 PNG 4개뿐이다.

## 저장

- 앱이 쓰는 키는 `fd_data_v2`와 `fd_data_v2_unreadable…`뿐이다. `fd_data_v1`에 쓰거나 지우면 안 된다(옛 판 원본).
- `fd_`로 시작하지 않는 저장소 키를 건드리면 안 된다 — 같은 주소의 가계부 앱 데이터다.
- 모든 쓰기는 `save()`/`writeState()`를 거친다. 쓰기가 실패하면(용량 초과 등) 화면 상태를 바꾸기 전으로 되돌리고 알림을 띄운다. 실패를 삼킨 채 화면만 바뀐 상태로 두면 안 된다.
- 기록을 바꾸는 모든 경로는 그 방문과 가게의 `updatedAt`을 함께 갱신한다(`touch`). 백업 합치기가 이 값에 기대므로, 빠뜨리면 다른 기기 백업에 조용히 덮인다.
- 고치기 저장은 사용자가 바꾼 칸만 다듬는다. 바꾸지 않은 값이 공백 하나라도 달라지면 위반이다.
- 정리 함수는 모르는 필드를 지우면 안 되고, 줄을 버리면 안 된다.
- 사진 지우기(`photoDel`)는 반드시 `photoInUse`가 거짓인 사진에만, 되돌리기 시간이 끝난 뒤에 한다.

## 화면

- 입력 중에 폼·검색창 노드를 바꾸면 안 된다. 검색 입력은 `renderList()`만, 폼 안의 변화는 해당 노드만 바꾼다. 확인 방법: 글자를 치는 동안 `document.activeElement`가 같은 노드로 남아야 한다.
- 정렬·"가장 최근" 비교는 문자열 비교(`cmp`)로 한다. 날짜를 빼거나 숫자로 바꿔 빼지 않는다(빈 날짜가 섞이면 NaN이 되어 순서가 깨진다).
- 사용자·파일에서 온 글은 `esc`를 거쳐야 `innerHTML`에 들어갈 수 있다. 링크는 `linkHTML`만 쓴다(http/https만 링크).
- 입력 칸 글자 크기는 16px 이상(작으면 아이폰이 화면을 확대한다). 375px 폭에서 가로로 넘치면 안 된다.
- 새 화면은 `:root`의 색·모서리 기준값과 `fd-` 클래스 접두를 쓴다. 바탕은 상아·베이지, 강조는 카라멜, 모서리는 크게 둥글게(버튼·칩은 알약 모양).
- 화면 문구는 쉬운 한국어로 쓴다. 사용자는 개발자가 아니다.

## 확인 문턱 (합치거나 올리기 전에)

1. 문법 검사가 `blocks: 1`과 `문법 정상`을 출력한다(명령은 operations.md).
2. 바꾼 부분을 브라우저 375px 폭에서 직접 눌러 보고, 누른 것과 보인 것을 남긴다. 자동 테스트는 없다.
3. 저장·지우기·백업을 건드렸으면: 확인용 데이터를 넣고, 바꾸기 전후 `fd_data_v1` 문자열이 같은지, 지운 뒤 되돌리기로 사진까지 돌아오는지 본다.
4. 카카오 키가 없어 확인하지 못한 것은 "확인하지 못함"으로 적는다.

## 커밋과 브랜치

- 커밋 메시지는 한국어, "~한다"체로, 무엇이 바뀌는지 쓴다.
- GitHub Pages는 `main` 브랜치를 내준다. `main`에 push하면 곧 사용자 폰에 반영되므로, 확인 문턱을 넘은 것만 `main`에 올린다.
