# 보안

## 지키는 것

- 사용자의 맛집 기록과 사진. 이 기기의 브라우저 저장소(localStorage `fd_data_v2`, IndexedDB `fd_photos`)에만 있다.
- 로그인·계정·서버가 없다. 누가 이 폰의 앱을 열면 기록을 볼 수 있다. 앱 안 잠금은 없다(만들지 않았다).

## 바깥으로 나가는 것

| 무엇 | 언제 | 무엇이 나가나 |
|---|---|---|
| 카카오 장소 검색 | 사용자가 위치 검색에 검색어를 넣을 때 | 검색어, 키, 이 페이지 주소 |
| 카카오 지도 | 지도 화면을 열 때 | 지도 타일 요청(보이는 영역) |
| 백업 파일 | 사용자가 공유 시트나 내려받기로 직접 내보낼 때 | 모든 기록과 사진 전부 |

기록 내용이 자동으로 나가는 길은 없다. 이 밖의 바깥 요청을 새로 만들지 않는다.

## 화면에 넣는 글

- 사용자가 적은 글과 백업 파일에서 들어온 글은 모두 HTML 이스케이프(`esc`)를 거쳐 화면에 들어간다. 이스케이프 없이 `innerHTML`에 넣지 않는다.
- 링크는 `http://` 또는 `https://`로 시작할 때만 누를 수 있는 링크(새 창, `rel="noopener"`)로 만든다. 그 밖의 값(`javascript:` 등)은 글자로만 보여 준다. 백업 파일은 남이 만든 것일 수 있으므로 이 규칙에 예외를 두지 않는다.

## 백업 파일 불러오기

- `app`이 `food-diary`이고 `places`가 배열인 파일만 받는다. 들어온 값은 저장 전에 정리 함수를 거친다(문자열·숫자·배열 모양 확인).
- 불러오기는 기기의 기록을 지우거나 덮지 않고 더하기만 한다. 같은 id면 `updatedAt`이 늦은 쪽이 이기므로, 미래 날짜가 박힌 파일은 기기의 같은 기록 내용을 바꿀 수 있다 — 확인 문구에 "더 최근 것으로 바뀌는 기록" 수가 나오는 이유다.

## 카카오 키

- 카카오 JavaScript 키는 `index.html`의 `KAKAO_JS_KEY` 상수에 사용자가 직접 넣는다. 원래 웹 페이지에 드러나는 값이고, 카카오 개발자 콘솔에 등록한 도메인에서만 동작한다.
- 등록할 도메인: `https://yooonji13-commits.github.io`(실제 사용), `http://localhost:4175`(확인용).
- REST API 키나 어드민 키는 넣지 않는다 — 그 키들은 도메인 제한이 없어 공개 저장소에 올라가면 남이 쓸 수 있다.
- 키 발급·도메인 등록은 사용자가 한다. 작업하는 쪽이 계정을 만들거나 키를 입력하지 않는다.

## 같은 주소를 쓰는 다른 앱

GitHub Pages 주소 `yooonji13-commits.github.io`는 `money-planner`와 같은 출처다. 그래서 두 앱은 같은 localStorage·IndexedDB 공간을 쓴다. 이 앱의 키는 모두 `fd_`로 시작하고(`fd_data_v1`, `fd_data_v2`, `fd_data_v2_unreadable…`, IndexedDB `fd_photos`), 가계부는 `mp_`로 시작한다. **`fd_`가 아닌 키는 읽지도 쓰지도 지우지도 않는다.** `localStorage.clear()` 같은 통째 지우기를 앱 코드에 넣지 않는다.
