# 알아 둘 것

## 확인 작업

- **`file://`로 열면 저장이 안 된다.** localStorage·IndexedDB가 막혀 저장·백업이 전부 실패한다. 반드시 http로 연다(`node .claude/serve.js`로 띄운 `http://localhost:4175`).
- **앱 화면에서 저장소에 값을 넣으면 앱이 덮어쓴다.** 앱은 열 때 읽은 상태를 들고 있다가 저장할 때 통째로 쓴다. 확인용 데이터는 같은 출처의 없는 주소(`http://localhost:4175/__seed`, 서버가 404를 준다)에서 넣고, 그다음 `/index.html`로 이동하고, 들어갔는지 먼저 읽어 본다.
- **숨겨진 미리보기 창에서는 `.blur()`가 `focusout`을 일으키지 않는다.** 문서에 시스템 포커스가 없어서다. 이름 칸에서 손을 뗄 때 도는 같은 가게 확인을 시험하려면 `el.dispatchEvent(new FocusEvent('focusout', {bubbles:true}))`를 직접 보낸다. 실제 아이폰의 손 떼기는 이렇게 확인되지 않는다.
- **캡처한 화면이 이전 상태이거나 잘려 보일 때가 있다.** 미리보기 창 캡처가 애니메이션 도중이거나 늦게 갱신된다. 넘침·값은 `scrollWidth`·저장소 값을 읽어서 판단한다.
- **카카오 없이 위치 검색·지도 흐름을 시험하는 법**: 페이지에서 가짜 `window.kakao`를 넣는다(`maps.load(cb)`, `maps.services.Places` + `keywordSearch`, `maps.Map`, `LatLng`, `LatLngBounds`, `CustomOverlay`, `event.addListener`). `loadKakao()`는 `kakao.maps.services`가 이미 있으면 스크립트를 불러오지 않고 바로 성공한다. 가짜는 저장소에 커밋하지 않는다.
- **사진 확인용 데이터**: `/__seed`에서 IndexedDB `fd_photos`(store `photos`, keyPath `id`)에 `{id, full: Blob, thumb: Blob}`을 넣고 기록의 `photos`에 그 id를 넣는다.

## 카카오

- **키는 등록된 도메인에서만 동작한다.** `localhost:4176`처럼 등록하지 않은 포트에서는 키가 있어도 실패한다. 실제 키로 확인할 때는 `http://localhost:4175`를 쓴다(등록 대상).
- 실패한 불러오기는 기억하지 않는다. 다음 시도에서 다시 불러온다(지도·위치 검색의 "다시 해 보기"). 키가 비어 있으면 요청 자체를 보내지 않는다.
- SDK가 이미 불러와진 뒤 인터넷이 끊기면 검색은 "검색하지 못했어요"라는 일반 안내를 띄운다(연결·키 안내가 아니다).
- 지도는 시트가 다 올라온 뒤(약 0.3초) 만들어야 크기를 제대로 잰다. 시트가 움직이는 중에 만들면 지도가 회색 일부만 그려진다.

## 세 군데에 같은 모양으로 있는 코드

- 위치를 골랐을 때 "이름은 비었을 때만 채우고, 종류는 안 골랐을 때만 골라 두고, 종류 칩을 다시 칠하는" 처리와 종류 칩 누르기 처리가 방문 폼(`openVisitForm`), 가게 정보 폼(`openPlaceForm`), 가고 싶은 곳 폼(`openWishForm`)에 각각 있다. 이 규칙을 바꿀 때는 세 곳을 함께 바꾸지 않으면 폼마다 다르게 동작한다.

## 알림과 되돌리기

- **새 알림이 되돌리기 알림을 덮던 문제**: 지운 직후 다른 저장("고쳤어요 ✨")을 하면 알림 자리가 바뀌어 되돌리기 버튼이 사라지고, 7초 뒤 지우기가 확정되었다. 지금은 되돌리기를 기다리는 동안 뜨는 알림이 되돌리기 버튼을 남기도록 되어 있다(`showUndo`/`undoToast`). 알림을 새로 만들 때 `toast()`를 거치면 이 동작이 유지된다.
- 되돌리기를 기다리는 가게는 `state`에서 빠져 있다. 그래서 그 가게가 쓰는 사진을 "아무도 안 쓴다"고 잘못 판단해 지우지 않도록 `photoInUse`가 기다리는 가게의 방문까지 본다. 사진을 지우는 새 경로를 만들면 반드시 `photoInUse`를 거친다.
- 앱을 닫으면(`pagehide`) 기다리던 지우기는 확정된다.

## 아이폰·배포

- **홈 화면 앱과 사파리 탭은 저장 공간이 따로다.** 사파리 탭에서 넣은 기록은 홈 화면 앱에서 보이지 않는다. 사용자에게 "홈 화면 앱에서 쓰세요"라고 안내하고, 옮겨야 하면 백업 파일을 쓴다.
- 사파리 탭으로만 쓰면 오래 안 쓸 때 iOS가 저장 공간을 지울 수 있다. 홈 화면 앱은 그 대상이 아니다. 사진을 처음 넣을 때 `navigator.storage.persist()`를 요청한다.
- GitHub Pages는 push 뒤 1~2분 안에 반영되지만 캐시 때문에 몇 분 늦게 보일 수 있다. 홈 화면 앱은 완전히 닫았다가 다시 열어야 새 파일을 읽는다.
- 같은 `github.io` 주소의 가계부 앱과 저장 공간을 함께 쓴다. 확인 중에 `localStorage.clear()`를 하면 같은 출처의 가계부 데이터도 지워진다 — 로컬 확인 서버(localhost)에서만 하고, 실제 주소에서는 하지 않는다.

## 사진

- `<img>`로 읽어 캔버스에 그리면 사진의 회전(EXIF) 정보가 반영된다(현재 사파리·크롬). `createImageBitmap`은 회전 처리가 브라우저마다 달라 쓰지 않는다.
- 아이폰에서 고른 HEIC 사진은 사파리가 파일 입력으로 넘길 때 JPEG로 바꿔 준다.
